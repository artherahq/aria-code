# Code tools and logistics data boundaries

`CoderAgent` reads and writes only within its configured `output_dir`. File tool paths and command working directories must be relative to that directory. A symlink that resolves outside it is rejected. `run_command` uses an argument list without a shell and requires a host-supplied `command_approval(argv, cwd)` callback for every invocation. Without approval, the tool returns an error and runs nothing. The host is responsible for presenting the exact command to the user and deciding whether to grant execution. `ask_user` only returns an actual answer supplied by `on_user_question`; without that callback it returns an unavailable error. Screenshot capture is currently unavailable and is reported as such.

`tool_analyze_logistics_data` accepts either `waybills` or a CSV/JSON `file_path`. If neither is provided, it reads an existing `~/.aria/erp_warehouse.db` in read-only mode. Missing or empty sources return an error. Each waybill requires a non-negative numeric `total_cost`; missing delivery status is excluded from the on-time denominator. A billed weight more than 20% above actual weight is flagged for review, not called proven overbilling: dimensional-weight and contract terms must be checked separately. The tool does not estimate savings without contract rates. Its `source` field identifies the records used for the report.
